# Kama Store — متجر إلكتروني (Next.js + TypeScript + Tailwind + Supabase)

متجر عربي RTL مستوحى من تجربة المتاجر الكبرى بهوية Kama Store الخاصة (شعار نصي أصلي، بدون أي علامات تجارية لغيرنا).

> **حالة المشروع بصراحة:** الكود مكتوب بالكامل، لكنه **لم يُشغَّل ولم يُبنَ بعد** — البيئة التي كُتب فيها لا تسمح بتثبيت حزم npm، فلم يتم `npm install` ولا `npm run build`. أول خطوة عندك هي تنفيذ الأوامر أدناه وإرسال أي أخطاء تظهر لإصلاحها. راجع قسم «ما تم التحقق منه».

## المميزات

| المجال | الموجود |
|---|---|
| الواجهة | شريط إعلانات، Header (شعار، بحث، حساب، مفضلة، سلة)، قائمة أقسام، Banner، الأكثر مبيعًا، عروض اليوم، مقترحة، جديدة، العلامات التجارية، Footer، متجاوب، RTL |
| المنتجات | صفحة لكل منتج: صور متعددة، سعر قبل/بعد الخصم ونسبته، مخزون، قسم، علامة، تقييمات، منتجات مشابهة، ألوان/مقاسات |
| البحث | بالاسم/العلامة/الوصف، حسب القسم، فلتر السعر والتقييم والعلامة، ترتيب بالسعر/الأكثر مبيعًا/الأحدث/التقييم |
| الحسابات | تسجيل، دخول، خروج، استعادة كلمة المرور، ملف شخصي، عناوين، سجل الطلبات، المفضلة (Supabase Auth — كلمات المرور مشفّرة لدى Supabase) |
| السلة | إضافة/حذف/تعديل كمية، إجمالي، خصم كوبون، شحن، حفظ بعد التحديث، منع تجاوز المخزون |
| الطلب | Checkout، عنوان، شحن، دفع، مراجعة، رقم طلب فريد، صفحة نجاح، سجل الطلبات |
| الإدارة | `/admin`: إحصائيات، منتجات (إضافة/تعديل/حذف/رفع صور/خيارات)، أقسام، مخزون، طلبات وتغيير حالتها، عملاء، كوبونات، عروض، تقييمات |
| الأمان | RLS على كل الجداول، الأسعار والمخزون والشحن والكوبون تُحسب داخل دالة `create_order` في قاعدة البيانات (أي سعر من المتصفح يُتجاهل)، حماية `/admin` في middleware + السيرفر + RLS، لا مفاتيح سرية في الواجهة |

## الدفع

- **الدفع عند الاستلام: يعمل.**
- **الدفع بالبطاقة: غير مفعّل.** لم يتم ربط أي بوابة ولا توجد مفاتيح. الخطوات في أعلى `src/lib/payments.ts`. لا يُخزَّن أي بيانات بطاقات في هذا المشروع.

## التشغيل محليًا

المتطلبات: Node.js 20+.

```bash
npm install
cp .env.example .env.local     # ثم عبّئ المفاتيح (انظر القسم التالي)
npm run dev                    # http://localhost:3000
npm run typecheck
npm run build
```

بدون مفاتيح Supabase يعرض الموقع صفحة «الإعداد غير مكتمل» بدل أن ينهار.

## إعداد Supabase

1. أنشئ مشروعًا على https://supabase.com.
2. **SQL Editor** → شغّل محتوى `supabase/schema.sql` كاملًا (مرة واحدة على مشروع فارغ). ينشئ الجداول: `profiles` (يمتد من `auth.users`)، `products`، `categories`، `product_images`، `product_variants`، `carts`، `cart_items`، `orders`، `order_items`، `addresses`، `payments`، `reviews`، `favorites`، `coupons` (+ `app_settings`)، مع RLS ودوال `create_order` و`validate_coupon` و`admin_stats` وbucket الصور `product-images`.
3. شغّل `supabase/seed.sql` لإضافة أقسام مبدئية (اختياري، قابلة للتعديل). لا توجد منتجات تجريبية افتراضيًا. `supabase/seed_demo.sql` منتجات وهمية للاختبار فقط — لا تشغّله في موقع حقيقي.
4. **Project Settings → API**: انسخ `Project URL` و`anon public key` إلى `.env.local`.
5. **Authentication → URL Configuration**: ضع `Site URL` = رابط موقعك، وأضف `http://localhost:3000/**` و`https://your-domain.com/**` ضمن Redirect URLs (مطلوب لتأكيد البريد واستعادة كلمة المرور).
6. **Authentication → Providers → Email**: قرر تفعيل «Confirm email». عند تفعيله يصل العميل بريد تأكيد (يلزم SMTP؛ خدمة Supabase المدمجة محدودة جدًا للإنتاج).

### إنشاء أول مدير (Admin)

لا توجد ترقية للمدير من الواجهة عمدًا. سجّل حسابًا من الموقع ثم نفّذ في SQL Editor:

```sql
update public.profiles set role = 'admin' where email = 'YOUR-EMAIL@example.com';
```

ثم افتح `/admin`.

## النشر على Vercel

1. ارفع المشروع إلى GitHub.
2. Vercel → **Add New Project** → اختر المستودع (يُكتشف Next.js تلقائيًا).
3. **Environment Variables**: أضف `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` و`NEXT_PUBLIC_SITE_URL` (رابط الإنتاج).
4. Deploy، ثم أضف رابط الإنتاج في Supabase → Authentication → URL Configuration.

## ما تم التحقق منه وما لم يتم

- ✅ كُتب كل الكود وSQL والتوثيق.
- ✅ فُحص اتساق الأنواع بين `src/lib/*` والصفحات عبر `tsc` مع تعريفات بديلة للحزم غير المثبتة (فحص محدود، لا يغني عن `npm run typecheck`).
- ❌ لم يُنفَّذ `npm install` / `npm run build` / `npm run dev`.
- ✅ شُغّل `schema.sql` و`seed.sql` على Postgres 16 محلي (مع بدائل لمخططي `auth`/`storage`) ونجحت 56 من 56 اختبارًا في `supabase/tests/`: عزل بيانات المستخدمين (RLS)، منع الترقية إلى أدمن، حساب السعر والشحن والكوبون داخل `create_order`، رفض تجاوز المخزون، استرجاع المخزون عند الإلغاء، التقييم لمن اشترى فقط.
- ❌ لم يُشغَّل `schema.sql` على مشروع Supabase حقيقي (سياسات Storage ورفع الصور وإعدادات Auth لم تُختبر هناك).
- ❌ لم يُختبر تسجيل الدخول ولا رفع الصور ولا الواجهة على الموبايل.
- ❌ بوابة الدفع الإلكتروني غير مربوطة.
- ⚠️ نصوص الواجهة (عدا `src/lib/i18n.ts`) مكتوبة مباشرة بالعربية؛ إضافة الإنجليزية تتطلب نقلها إلى قاموس الترجمة.
- ⚠️ صفحات السياسات (`/info/...`) نصوص عامة تحتاج مراجعة قانونية قبل الإطلاق.
- ⚠️ أسعار الشحن (60 / 120 / مجاني فوق 1000 ج.م) افتراضات في `src/lib/shipping.ts` ودالة `create_order` ويجب أن تتطابقا.
